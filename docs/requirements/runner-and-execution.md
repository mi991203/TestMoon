# 执行与 Runner

- RUN-001：保存手动任务；任务内测试项串行、任务间可按限额并发。调试、单用例和场景共用执行链路。
- RUN-002：执行开始读取最新定义并固定快照，历史记录不受后续编辑影响。没有实际断言的测试项为未校验，不计通过。
- RUN-003：报告保存汇总、步骤状态、断言、耗时、脱敏请求响应和脚本日志；默认保留 30 天，可由平台配置。
- RUN-004：支持主动取消，请求、脚本和整次执行超时，限制并发、请求响应及日志体积。取消不能撤销已发出的请求。
- RNR-001：用户选择公共 Runner 或项目独享私有 Runner；私有 Runner 离线拒绝启动，失联标记异常，不自动重试或回退到公共 Runner。
- RNR-002：Runner 以 Docker 镜像和 Compose 示例交付，主动 HTTPS 注册、心跳、拉取和回传，不开放私网入站端口。
- RNR-003：每次执行独立容器。管理进程持有 Docker API 权限；执行容器不获得 Docker、平台凭证或宿主文件，不开放直接网络。
- RNR-004：Go 负责 HTTP 调用和网络策略，Node LTS 执行 JS，脚本 HTTP 同样经 Go。公共仅公网；私有允许部署网络。
- MQ-001：Kafka 用于执行服务内部任务分发，不向 Runner 暴露 broker。Outbox、去重及原子领取避免消息重投导致重复执行。

首版没有容量 SLA，限制可配置；实际环境、检查结果及未验收项须如实记录。
