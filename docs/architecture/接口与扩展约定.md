# 接口与扩展约定

## 对外接口与协议

浏览器只访问网关。每个操作拥有独立Request/Response和HTTP动作路径，创建、更新、删除及不同资源分别定义。`protocols/common/v1/common.proto`的通用Request/Reply已移除。

例如创建接口 `POST /api/testing/v1/apis/create`：

```json
{
  "org_id": "组织UUID",
  "project_id": "项目UUID",
  "name": "查询订单",
  "document": {
    "protocol": "http",
    "request": {
      "method": "GET",
      "url": "{{base_url}}/orders",
      "auth": {"type": "none"}
    }
  }
}
```

成功响应直接是 `{"resource":{...}}`，不再包含data信封。更新接口另传id、revision；创建接口不接受更新专用字段。固定字段中的未知属性会返回400。错误沿用gRPC标准状态映射和message字段，网关认证错误也可能是纯文本。Cookie和X-CSRF-Token机制保持不变；前端会话Hook在加载后初始化CSRF。

`protocols/testing/contracts/v1/testing.proto`定义HTTPRequest、Auth、API、TestCase、Scenario、Environment、Task、Snapshot、执行结果与Mock响应。仅导入的开放Schema使用Struct，断言/Mock条件中的任意JSON期望值使用Value；headers/query/variables使用明确值类型的map。HTTP body、JS脚本及导入文件内容是协议文本，不解析成通用请求信封。导入预览条目使用oneof区分具体定义。

protobuf JSON采用snake_case；int64（如revision、毫秒耗时）响应为字符串，输入接受字符串或数字；Timestamp为RFC3339。HTTP响应多值头为 `{"Content-Type":{"values":["application/json"]}}`。Runner通过明确的PB契约与控制面通信，共享领域模型只用于执行编排和容器IPC。

| --- | --- |
| /api/platform/v1/ | login、logout、session、change-password；users/create-user/reset-password/set-user-status；organizations/create-organization/update-organization；members/set-member/remove-member |

完整字段和路由以各服务proto及同目录生成的swagger为准。类型化TS客户端在 `libs/frontend/api/src/generated.ts`，例如 `core.createAPI`、`core.listTestCases`、`execution.runCase`。

用例列表可传api_id：指定UUID查询该接口的用例，显式空字符串查询未关联或关联接口失效的用例，省略则查询全部。关联通过test_case_definitions.api_id及作用域SQL过滤后应用1000条上限。其他资源列表支持search和可选folder_id，详情使用get按ID读取；报告最近100次，大规模游标分页未实现。

执行接口各自负责一种来源：debug-http接收debug内联用例；run-case接收case_id；run-scenario接收scenario_id；run-task只接收task_id并加载已保存配置。前3者可指定environment_id、runner_id、timeout_seconds。runner_id是public或项目私有节点UUID。所有执行都要求idempotency_key，在组织、项目、用户内隔离；同键同请求返回原run，不同内容返回409。

本次属于接口契约变更，旧data信封及save-resource/start等通用路由不再可用；前端、控制面服务、Runner需使用本仓库同一版产物。数据库历史定义则由兼容迁移保留。

## 文档与变量模型

API文档包含protocol=http、request和description，可保留导入Schema。HTTPRequest含method、url、headers/query字符串映射、body_type（json/text/form）、body、auth、timeout_ms。auth类型none/basic/bearer/api_key；APIKey支持header/query。HTTP方法支持GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS。

Case支持api_id引用或独立request、override覆盖、variables、before/after操作、assertions、extractions。步骤可引用case_id或内联inline，补充override和variables，并设置continue_on_failure。RequestPatch区分未指定和显式空值，headers/query按键覆盖同名值，未提供的键保留。UI覆盖编辑器填写完整覆盖输入。

环境格式：`{variables:{base_url:{value:"https://example.com",secret:false},credential:{value:"...",secret:true}}}`。普通case/步骤变量为字符串映射；运行时优先级：局部/提取变量 > 当前用例/步骤变量 > 环境 > 集合变量 > globals。`{{name}}`递归替换最多10层，未定义和循环引用明确报错。表单先解析键值、替换值再编码，避免变量中的`&`改变字段结构。

同场景共享提取变量与运行时环境，任务不同测试项隔离；同项共享CookieJar。默认失败停止当前场景，其余项继续执行。运行变量不写回持久化环境或定义。

断言支持status、duration、text、header、json来源；JSON路径为JSON Pointer（`/data/items/0/id`），operator为eq/neq/contains/exists/regex/lt/lte/gt/gte。提取同样使用source/path，填入variable，可标记secret。

## JS v1 支持范围

操作结构为 `{type:"javascript",version:1,script:"..."}`。Node执行脚本，每个操作使用独立进程，状态通过受控JSON传递；前置操作可更新请求，后置操作修改不改变已发送请求记录。

- `pm.variables/environment/collectionVariables/globals`：get、set、unset、has、clear、toObject、replaceIn；pm.variables.get按完整优先级查找。
- `pm.request`：method、url、headers（get/has/upsert/add/remove/toObject/each）、body.raw/body.update。
- `pm.response`：code、status、responseTime、json()、text()、headers；to.have.status/header/jsonBody、to.be.json。
- `pm.test(name, fn)`：同步、Promise及done回调；`pm.expect`使用Chai。只有实际执行的断言计数，空测试不算通过。
- `pm.sendRequest`：URL或请求对象，Promise或回调；HTTP同样经过监督进程网络策略和超时。支持raw和urlencoded请求体。
- `pm.info`：requestName、eventName、iteration=0、iterationCount=1。
- `console.log/info/warn/error/debug`：每操作最多200条、合计32KiB，报告再统一脱敏与裁剪。

不支持require/import外部包、文件/数据库/宿主进程API、Vault、可视化、iterationData、跳转/循环控制、OAuth流程、动态变量生成器和Postman全部沙箱API。未知pm属性明确报错；本支持范围不是完整Postman兼容承诺。JS vm不是安全沙箱，实际隔离依赖每次执行的Docker容器。

## 导入边界

预览仅解析不写资源，返回batch_id/entries/diagnostics，有效1小时且绑定发起人。用户选择条目及更新目标，更新需要现有revision；提交事务内一次性验证并写入，不接受缺失依赖，不做同名自动覆盖，同批预览不能重复使用。预览计划加密保存，原始文件不另行落盘。

Postman Collection v2.1支持请求URL、启用的headers、raw JSON/文本、urlencoded、Basic/Bearer/APIKey及认证继承、collection变量。保留API/用例目录，生成API与用例、整个集合的顺序场景；将集合→目录→请求的前后置脚本顺序展开到用例。最多100请求，超出需拆分集合。已识别的不支持脚本产生诊断，运行仍严格报错；上传文件/不支持认证会诊断并跳过请求。首版不导入Postman环境文件、folder变量或保存响应示例为Mock。

OpenAPI 2.0/3.0/3.1支持JSON/YAML，单文件内部引用、全局首个server或host/basePath、方法/路径、查询与Header参数、JSON/文本/form请求体及JSON example；原操作Schema保存在API契约。路径参数转换为变量，由环境/用例填写。没有example时不会自动生成深层Schema示例或断言，需补充测试输入。不访问外部$ref，不导入外部文件。安全方案和操作级server会诊断并要求手动配置；不转换OpenAPI为自动化用例、完整JSON Schema验证器或OAuth认证流程。

## 后续扩展点

新增协议需添加版本化请求模型、校验、Runner capability和执行适配器；控制面仍复用快照、调度和报告。gRPC/WS当前不执行，不能仅增加前端协议选项。

新增前后置操作使用type/version路由到独立适配器，不能绕过运行限额与网络策略。新增应用复用identity和gateway，自己管理项目与应用权限。依赖版本集中管理，服务数据边界保持独立。

## Web导航与历史兼容

测试应用使用React Router，basename为`/apps/testing`。URL查询参数org和project保留当前数据范围，切换组织/项目时回到该功能列表，不携带旧资源ID。

| 页面 | 路由（省略basename） |
| --- | --- |
| API测试概览/目录 | /api-testing、/api-testing/folders/:folderId |
| API调试 | /api-testing/apis/:apiId/debug |
| 当前接口用例 | /api-testing/apis/:apiId/cases |
| 创建关联用例 | /api-testing/apis/:apiId/cases/new |
| 用例详情 | /api-testing/cases/:caseId |
| 历史未关联用例 | /api-testing/unlinked |
| 场景/环境详情 | /scenario/:id、/environment/:id |
| 任务/Mock规则详情 | /tasks/:id、/mock/:id |
| 文档/报告详情 | /documents/:id、/reports/:id |

新建资源使用new占位路由；保存后跳转资源详情或对应列表。详情按ID直接查询，避免列表上限导致已有资源无法打开。原有/api和/case导航路径保留重定向。目录维护和执行参数等操作仍可使用对话框，主要业务详情不再使用Modal/Drawer。

历史兼容通过[数据模型迁移](数据模型与迁移.md)实现。独立用例保留原request，关联用例保留原api_id、UUID、revision、脚本、断言及场景引用；失效关联仍在未关联入口展示。旧加密document保留为迁移来源，不再承担新版本业务写入。
