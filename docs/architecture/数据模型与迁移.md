# 数据模型与迁移

数据库仍按服务隔离，GORM实体在每个服务的model，连接、存取和兼容迁移在dao。建表快照在 [deploy/database](../../deploy/database/)，用于新库初始化和结构审阅；已有库由服务启动迁移，不通过重新执行CREATE TABLE升级。SQL快照不包含业务数据或凭证。

## 表与字段归属

| 服务/库 | 表 | 主要内容 |
| --- | --- | --- |
| identity | users、organizations、members | 账号、组织、成员；密码哈希、会话epoch；会话本身在Redis |
| core | projects、members | 项目及组织/项目/用户角色 |
| core | resources | 公共目录元数据：org_id、project_id、kind、name、folder_id、revision |
| core | api_definitions | protocol、description、加密request与动态schema |
| core | test_case_definitions | 内部name、显式api_id索引；独立request、覆盖、变量、脚本、断言及提取的具体加密字段 |
| core | scenario_definitions | 内部name；步骤列表和集合变量分别加密保存 |
| core | environment_definitions | 带secret标记的环境变量，加密保存 |
| core | resource_folders | 目录对应的asset_kind |
| core | shares、import_batches | 分享范围/密码哈希/有效期，加密预览计划 |
| core | schema_migrations | 资源定义回填版本及完成标记 |
| execution | tasks | name、revision、items_json、environment_id、runner_id、timeout_seconds、config_version |
| execution | runs | 状态、任务/用户/节点归属、幂等哈希、队列截止、租约、起止时间；加密快照和结果 |
| execution | runners | 公共/私有归属、在线时间、并发、能力、注册与机器凭证哈希 |
| execution | outboxes、consumed_events、budgets | 投递、消费去重、组织执行预算锁 |
| mock | endpoints | 项目匿名入口 |
| mock | rules | endpoint_id、method、path、priority、status、delay_ms；headers/body/conditions分别加密；definition_version |

resources与对应定义表共用原UUID，并同时携带组织、项目和软删除范围。普通业务表继承Base，使用`gorm.io/plugin/soft_delete.DeletedAt`的毫秒模式；迁移标记、消费去重、预算锁等控制表按其用途定义主键。跨服务不使用数据库外键或跨库查询，业务引用在所属服务中校验。

可查询、关联、排序的固定字段独立建列。headers、参数、变量、步骤和脚本属于具备明确类型的聚合结构；敏感部分加密后保存到对应字段。执行快照/报告是不可变或租约控制的整体记录，继续整体加密。加密JSON不替代对外的强类型PB定义。

## 事务与并发

- 资源创建、更新、删除同时处理目录记录和具体定义；revision条件更新失败返回409，任一表失败回滚全部写入。
- 资源详情、列表及快照在同一事务中读取元数据和定义，避免跨版本组合。用例按api_id在SQL过滤后限量。
- 任务更新同样采用revision条件写入。Mock规则沿用既有更新语义，没有新增版本锁。
- 导入提交在一个事务中写入目录及具体定义，保留引用校验和预览一次性使用机制。

## 历史迁移

启动顺序为建表/补列 → 兼容回填 → 服务监听。core用迁移版本行锁串行回填，将原resources.document解密到对应定义表，包括软删除记录。完成标记与回填处于同一事务；失败不写完成标记，修复后可重试。后续启动已完成的迁移直接跳过。

execution按config_version=0、mock按definition_version=0锁定并回填历史行，成功后标记1。新写入直接使用新字段。三类迁移都不改UUID、revision、删除标记和原创建/更新时间，不清表；遇到无法解密或解析的历史记录会终止启动并保留原数据。

旧document列保留为只读迁移来源，运行时Document字段标记gorm:"-"，不会再写入通用文档。旧列不是最新数据的镜像，回滚不能只切回旧二进制；应使用升级前备份或经过验证的反向迁移。生产升级前备份数据库，并同时升级服务、前端和Runner协议产物。
